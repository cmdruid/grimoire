# ③ TUI v0.1 — roadmap

**Status:** current — governing the `app` workstream (2026-08-15). Sub-project ③ of the
grimoire repurpose. The decision map for
the track: phases with gates and blocking edges; each phase gets its own implementation plan
before build (task-level detail lives there, never here). Governing decisions: the umbrella
(`docs/design/2026-08-07-grimoire-repurpose-design.md`, §4–5) and the approach settled at
brainstorm (2026-08-10/15, recorded below); the pack format is `docs/spec/pack-format.md`
(draft 5, format 1).

## Approach settled at brainstorm (binding for this track)

- **TUI-only v0.1.** `grimoire` launches straight into the TUI; no CLI verbs beyond trivia
  flags (`--version`, `--library <path>`, `--project <dir>`). CLI verbs and passthrough sugar
  are post-v0.1 layers over `grimoire-core`.
- **Local sources only.** Installs come from a local library clone (this repo, or any
  Vercel-format skills tree). No remote fetch, no registry search, no authoring, no
  file-watching in v0.1.
- **Two workflows, two screens:** the library screen (browse packs + loose skills, install to
  a scope — the `install.sh` dogfood loop made visual) and the project screen (per-agent
  scopes, lock-aware, install/remove at project scope).
- **Pack-dependence is opaque to the app** (owner, 2026-08-10): members render flat per the
  manifest; the app never assumes members are framework-bound or standalone.

## Cross-cutting foundations

- **Async posture:** the `skill` crate is async; `grimoire-core` adopts tokio and exposes
  async operations; the TUI runs ratatui over a tokio event loop. No sync façade.
- **Dependency policy:** `skill` pinned `=0.8.3` (the evaluated version; single-maintainer
  risk); vendor/fork is the documented fallback, kept real by the next bullet.
- **Seam types:** `grimoire-core` exposes its own thin domain types (library, scope, install
  plan, check report) — `skill` types never cross `grimoire-core`'s public API.
- **The hard seam rule stands:** crates never read `skills/` at build time; library content
  appears only as test fixtures (sandboxed throwaway trees, the proven harness pattern).
- **Theming:** themed verbs as action labels with plain aliases in help
  (`learn`/`install`, `forget`/`remove`, `peruse`/`list`); machine-facing vocabulary stays
  plain; no character names or show assets.
- **Naming:** app crate dir `crates/grimoire`, package `skill-grimoire`, binary `grimoire`
  (settled at ②, `docs/design/2026-08-08-repo-restructure-design.md`).

## Sequencing

Linear: 1 → 2 → 3 → 4. Each phase blocks on the previous; no parallel-eligible phases (the
track is one stream of work, and each phase consumes the previous phase's surface).

_Plan: `docs/design/2026-08-15-tui-phase1-implementation.md`. Delivered `Scope`/`scope_for`/

- **Goal:** the two library gaps ① recorded that a consumer hits immediately, closed.
- **Scope:** in: the §3 scope-path helper (given an install target, where the lock lives);

- **Gate:** new unit tests green; full workspace suite (36 + new) and clippy `-D warnings`
  green; `tests/clankshop.rs` still pins the live pack.
- **Risks:** low — additive, sync, no new dependencies.

## Phase 2 — grimoire-core: operations, no UI   *(requires: 1)*

- **Goal:** every v0.1 operation callable (and integration-tested) from plain async Rust.
- **Scope:** in: library model (enumerate packs + loose skills from a local path);
  scope/agent model (machine + project scopes over detected agents); install/remove for
  atoms and packs (symlink semantics matching `install.sh`, transactional pack install, lock
  read/write per spec §3/§7); the check operation (enumeration issues + lock drift as data);
  the tiny config (default library path). Out: any rendering, any TTY assumption, remote
  anything.
- **Gate:** sandboxed integration tests against throwaway fixture library/project trees
  cover both workflows end-to-end (discover → install → list → check → remove); no UI crates
  in `grimoire-core`'s dependency tree; workspace suite + clippy green.
- **Risks:** `skill` 0.8.3 API friction at the wrapping seam (install choreography is
  CLI-side upstream — core reassembles it from library pieces; mitigated by the ①-evaluation
  findings and the pinned reading reference in `repos/skill-rs`); lock semantics edge cases
  (mitigated: `grimoire-pack` lock I/O is already spec-tested).

## Phase 3 — TUI skeleton + library screen   *(requires: 2)*

- **Goal:** workflow (a) shippable: browse the library, install/remove visually.
- **Scope:** in: ratatui + tokio event loop (the new render path — spiked first and verified
  visually in isolation, per the plan discipline); library screen (packs with member
  rosters, loose skills, target-scope picker, confirm-then-install/remove with progress and
  failure states); ambient check surfaced as status on launch; themed verb labels. Out: the
  project screen, config editing UI.
- **Gate:** ratatui `TestBackend` smoke tests green; a real dogfood install of a skill and a
  pack from this clone through the TUI; workspace suite + clippy green.
- **Risks:** async event-loop ↔ render-loop integration (the spike is Task 1 of the phase's
  plan); long-running install ops blocking the UI (core ops run on tasks, UI stays
  responsive — the spike proves the pattern).

## Phase 4 — project screen + v0.1 close-out   *(requires: 3)*

- **Goal:** workflow (b) shippable; v0.1 dogfood-complete.
- **Scope:** in: project screen (open a project, per-agent scopes via detected agents,
  installed inventory, lock state, install/remove at project scope); ambient check on
  project-open; `--library`/`--project` flags + config default wiring; help overlay with
  plain aliases; release build instructions. Out: everything the brainstorm excluded
  (remote, search, CLI verbs, authoring, watching).
- **Gate:** both v0.1 workflows demoed end-to-end on a real project; a full dogfood session
  replacing `install.sh` for machine installs; workspace suite + clippy green; README's
  repo-layout section updated to "the TUI exists".
- **Risks:** per-agent scope diversity (Claude vs Codex layouts — mitigated: scope model and
  detection are Phase 2 surface, this phase only renders them); scope creep at close-out
  (the out-list is binding).
